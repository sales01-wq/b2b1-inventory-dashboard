# 수동 업로드 가이드 (ERP 자동 수집은 보류 중)

ERP 엑셀을 직접 내려받아 → 검사 · 이름 정리 → 드라이브 업로드 폴더 → Apps Script → 저장본 → 대시보드.
(자동 수집기 `npm start` 와 예약 업로드는 꺼져 있습니다. 코드는 나중을 위해 그대로 보존합니다.)

## 매번 하는 일 (Windows PC)
1. ERP 에서 엑셀 5개를 한 폴더에 내려받습니다: 가용재고조회, WMS창고재고관리(EMP), 일자별판매실적분석 **B2B1팀**, **B2B2팀**, 제품일정표.
   (상품마스터는 이 도구가 다루지 않습니다. 기존 방식 그대로 두세요.)
2. PowerShell, `collector` 폴더 (처음 한 번만 `npm ci`):
   ```powershell
   npm run pack -- "C:\내려받은\폴더"
   ```
   - 5개가 모두 있고 내용이 맞아야만 파일을 만듭니다 (전부 아니면 전무). 문제가 있으면 무엇을 고쳐야 하는지 알려 줍니다.
   - 파일 이름은 날짜가 달라도, `B2B1` / `B2B1팀` 이 섞여 있어도 알아보고 기존 이름 규칙으로 바꿉니다. 같은 종류가 여러 개면 가장 최신 파일만 씁니다.
   - 결과: 같은 폴더 안 `ERP_업로드_준비_날짜\` (엑셀 5개 + `ERP_BUNDLE_….zip` 1개). 드라이브에는 아무것도 쓰지 않습니다.
3. 드라이브 `업로드용` 폴더에 올립니다.
   - **지금 방식:** 엑셀 5개를 올립니다 (Apps Script 를 아직 안 바꿨다면 예전처럼 하나씩 처리됩니다).
   - **zip 은 선택입니다.** 엑셀 5개를 낱개로 올려도 한 묶음으로 전부 아니면 전무로 반영됩니다 (아래 단계 2 적용 후). `ERP_BUNDLE_….zip` 1개를 올려도 같습니다.
4. 5분 안에 반영됩니다. 대시보드 상단 안내에서 확인하세요:
   - "최근 업로드 문제": 반영하지 못했고 이전 정상 데이터를 보여 주는 중이라는 뜻입니다. 이유대로 고쳐 다시 올리세요.
   - "데이터가 오래되었습니다": 36시간 넘게 업데이트가 없었다는 뜻입니다.

## 브라우저에서 직접 올리기 (백업, 개인 화면에만 반영)
대시보드 `CSV / 엑셀 업로드` 에서 올리면 적용 전에 검사합니다: 머리글만 있는 파일, 파일 이름과 내용의 팀이 다른 판매실적은 적용할 수 없고(현재 데이터는 그대로), 행 수가 절반 아래로 줄면 확인 후 적용합니다.

## 한 번만 하는 설정 (기존 폴더 · 시트 · Apps Script 프로젝트를 그대로 사용 — 복사본을 만들 필요 없음)
### Apps Script: 두 단계로 (기존 프로젝트에 직접, 단계 1 은 동작이 전혀 바뀌지 않음)
**단계 1 — 새 파일 3개만 추가하고 읽기 전용 점검** (`collector/apps-script/` 의 `Batch.gs`, `SnapshotGuard.gs`, `DryRun.gs` 를 새 파일로 추가)
- 기존 코드는 건드리지 않으므로 이 단계에서는 아무것도 달라지지 않습니다 (새 함수를 부르는 곳이 아직 없음).
- 편집기에서 함수를 골라 ▶ 실행 → '실행 로그' 확인 (모두 읽기 전용, 시트 · 저장본 · 폴더를 바꾸지 않음):
  - `dryRunReport` — 지금 탭 목록(이름 · 행 수 · 종류), 상품마스터 탭 이름, 같은 종류 탭이 여러 개인지. **상품마스터 탭 이름이 `상품마스터…` 로 시작하는지 여기서 확인합니다.**
  - `dryRunSnapshot` — 지금 시트로 저장본을 만들면 검사를 통과하는지.
  - `dryRunBatch` — 업로드용 폴더에 올려 둔 파일들이 한 묶음으로 처리 가능한지 (파일 이동 · 시트 변경 없음).
**단계 2 — 연결 (별도 승인 후)** 기존 코드 4곳 수정 (`Batch.gs` 맨 아래에 정확한 문구): ① `checkForNewFilesInner_` 이름 → `checkForNewFilesInnerLegacy_` ② `buildSnapshot_` 이름 → `buildSnapshotLegacy_` ③ `doGet` bundle 에 `out.problem = readProblems_();` ④ 설정 저장의 이름을 `p.skey` 에서 읽기.
- 저장 후 **배포 → 배포 관리 → 새 버전**으로 배포해야 웹앱 주소가 유지됩니다. 문제가 생기면 ①②의 이름만 되돌리면 이전 동작입니다.
- 연결 뒤 동작: 업로드용 폴더의 파일(엑셀 5개 낱개 + 선택적으로 `ERP_BUNDLE_*.zip`)을 **한 묶음으로 전부 아니면 전무** 반영합니다. 하나라도 잘못되면(시트 종류가 이름과 다름, 데이터 없음, 같은 탭을 만드는 파일이 둘 등) **시트도 파일도 그대로** 두고 대시보드에 이유를 보여 줍니다. 문제 파일을 고치거나 지우면 다음 5분 주기에 반영됩니다. 바뀐 파일만 올리기 · 상품마스터 올리기는 기존처럼 됩니다.
- 시험은 평소 쓰는 업로드용 폴더에 `pack` 이 만든 파일을 올리는 것으로 충분합니다 (한 묶음이 실패해도 시트가 바뀌지 않는 것이 이 코드의 목적이므로, 단계 1 의 `dryRunBatch` 로 먼저 확인하고 올리세요).
- **API 키 교체와 `__설정` 정리 (같은 시점에 권장):** 지금까지 설정 저장이 인증 키를 설정 이름으로 시트 `__설정` 탭에 적었을 수 있습니다 (그리고 `/api/settings` 응답으로 로그인한 사용자에게 보였을 수 있습니다). ④와 `api/settings.js` 수정을 적용하고, API 키를 교체한 뒤(스크립트 속성 `API_KEY` / `API_KEY_NEXT`, Vercel `GAS_KEY`), `__설정` 탭의 옛 행(키 열에 긴 문자열이 있는 행)을 지우고 대시보드에서 기준 · 히어로 · 박스 정보를 다시 저장하세요.
### Vercel
- 미리보기 프로젝트(`inventory-dashboard-react-preview`)에 환경변수 `GOOGLE_CLIENT_ID`, `ALLOWED_DOMAIN`, `UPDATER_EMAILS`, `GAS_URL`, `GAS_KEY` 를 넣고 재배포합니다. 빌드는 `VITE_READ_ONLY=1` 그대로 둡니다 (대시보드가 서버 데이터를 바꾸지 않음).
- 구글 로그인용 OAuth '승인된 JavaScript 원본' 에 미리보기 주소를 추가합니다.
- 운영 사이트 전환(`web/` 로 빌드 변경, `VITE_READ_ONLY` 제거)은 미리보기 확인 후 **별도 승인**으로 진행합니다.
