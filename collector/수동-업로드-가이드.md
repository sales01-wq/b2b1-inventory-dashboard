# 수동 업로드 가이드 (ERP 자동 수집은 보류 중)

ERP 엑셀을 직접 내려받아 → 검사 · 이름 정리 → 드라이브 업로드 폴더 → Apps Script → 저장본 → 대시보드.
(자동 수집기 `npm start` 와 예약 업로드는 꺼져 있습니다. 코드는 나중을 위해 그대로 보존합니다.)

## 매번 하는 일 (Windows PC)
1. ERP 에서 엑셀 5개를 한 폴더에 내려받습니다: 가용재고조회, WMS창고재고관리(EMP), 일자별판매실적분석 **B2B1팀**, **B2B2팀**, 제품일정표.
   (상품마스터는 이 도구가 다루지 않습니다. 기존 방식 그대로 두세요.)
2. PowerShell, `collector` 폴더 (처음 한 번만 `npm ci`):
   ```powershell
   npm run pack -- "C:\내려받은\폴더"
   ```
   - 5개가 모두 있고 내용이 맞아야만 파일을 만듭니다 (전부 아니면 전무). 문제가 있으면 무엇을 고쳐야 하는지 알려 줍니다.
   - 파일 이름은 날짜가 달라도, `B2B1` / `B2B1팀` 이 섞여 있어도 알아보고 기존 이름 규칙으로 바꿉니다. 같은 종류가 여러 개면 가장 최신 파일만 씁니다.
   - 결과: 같은 폴더 안 `ERP_업로드_준비_날짜\` (엑셀 5개 + `ERP_BUNDLE_….zip` 1개). 드라이브에는 아무것도 쓰지 않습니다.
3. 드라이브 `업로드용` 폴더에 올립니다.
   - **지금 방식(Apps Script 를 아직 안 바꾼 경우):** 엑셀 5개를 올립니다.
   - **묶음 처리 코드를 적용한 뒤:** `ERP_BUNDLE_….zip` 1개만 올립니다 (일부만 반영되지 않고, 잘못된 파일이 있으면 시트가 하나도 바뀌지 않습니다).
4. 5분 안에 반영됩니다. 대시보드 상단 안내에서 확인하세요:
   - "최근 업로드 문제": 반영하지 못했고 이전 정상 데이터를 보여 주는 중이라는 뜻입니다. 이유대로 고쳐 다시 올리세요.
   - "데이터가 오래되었습니다": 36시간 넘게 업데이트가 없었다는 뜻입니다.

## 브라우저에서 직접 올리기 (백업, 개인 화면에만 반영)
대시보드 `CSV / 엑셀 업로드` 에서 올리면 적용 전에 검사합니다: 머리글만 있는 파일, 파일 이름과 내용의 팀이 다른 판매실적은 적용할 수 없고(현재 데이터는 그대로), 행 수가 절반 아래로 줄면 확인 후 적용합니다.

## 한 번만 하는 설정
### Google Drive
- 시험용으로 **업로드용 · 처리완료 폴더 복사본** 과 **대상 스프레드시트 복사본** 을 만듭니다 (운영 데이터는 건드리지 않습니다).
### Apps Script (먼저 복사본 프로젝트에서)
1. 복사본 프로젝트에 `collector/apps-script/ErpBundle.gs`, `SnapshotGuard.gs` 를 새 파일로 추가합니다.
2. 기존 코드 수정 (총 5곳):
   - `checkForNewFilesInner_` 안: `const filesIter` 줄 위에 `const bundleCount = processErpBundles_(sourceFolder, processedFolder);`, `if (total === 0) {… return 0;}` 의 `return 0` → `return bundleCount;`, `let processedCount = 0;` → `let processedCount = bundleCount;`
   - `buildSnapshot_()` 호출 2곳(`checkForNewFiles`, `runSnapshotJob`) → `buildSnapshotChecked_()`
   - `doGet` 의 `action === 'bundle'` 에서 `const out = {…}` 바로 아래에 `out.problem = readProblems_();`
3. `ErpBundle.gs` 의 `BUNDLE_PROTECTED_TABS` 가 실제 상품마스터 탭 이름과 맞는지 확인합니다 (`상품마스터_전체`).
4. 복사본에서 `pack` 으로 만든 zip 을 올려 시험 → 시트 · 저장본이 맞는지, 일부러 틀린 파일로 거부되는지 확인합니다.
5. 시험이 끝나면 **운영 Apps Script 에 같은 변경을 적용 (별도 승인 필요)**. 새 버전으로 배포해야 주소가 유지됩니다. API 키 교체(스크립트 속성 `API_KEY` / `API_KEY_NEXT`)도 이때 같이 합니다.
### Vercel
- 미리보기 프로젝트(`inventory-dashboard-react-preview`)에 환경변수 `GOOGLE_CLIENT_ID`, `ALLOWED_DOMAIN`, `UPDATER_EMAILS`, `GAS_URL`, `GAS_KEY` 를 **복사본 Apps Script 기준**으로 넣고 재배포합니다. 빌드는 `VITE_READ_ONLY=1` 그대로 둡니다 (대시보드가 서버 데이터를 바꾸지 않음).
- 구글 로그인용 OAuth '승인된 JavaScript 원본' 에 미리보기 주소를 추가합니다.
- 운영 사이트 전환(`web/` 로 빌드 변경, `VITE_READ_ONLY` 제거)은 미리보기 확인 후 **별도 승인**으로 진행합니다.
